### HIGH — Remaining 19 (All Blocked Upstream)

All 19 remaining HIGH CVEs are from a single root cause: `github.com/docker/docker` as an **indirect test-only dependency** of `testcontainers-go v0.40.0`.

**Why unfixable now:**

| Reason | CVEs | Notes |
|---|---|---|
| `docker/docker v29.3.1` not in Go module proxy | CVE-2026-34040 (5 modules) | Fix version published for Docker Engine, not yet reflected in pkg.go.dev |
| No upstream fix available at any version | CVE-2026-41567, CVE-2026-42306 (5 modules × 2) | Docker upstream has not released fix |
| Vendored Pipfile.lock inside testcontainers-go | urllib3@2.5.0 (4 findings in `dodo_health_monitor/vendor/`) | False positive — Python CI infra of the Go library itself, not our code |

**Risk context:** These CVEs affect the Docker daemon/client SDK. `testcontainers-go` is used exclusively in integration tests (not production code path). The staging cluster pods do not use testcontainers at runtime.

**Action:** Monitor for `docker/docker v29.3.1` publication in Go module proxy; run `go get github.com/docker/docker@v29.3.1` + `go mod tidy` in affected modules when available.
